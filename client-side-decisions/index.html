Client-side inference

A decision model in 23 megabytes

Everything on this page runs on your machine. The weights come from a CDN once, the tokenizer runs in your tab, and the text you type is scored locally and never sent anywhere. It is the architecture from the previous note at production size: a small encoder for the state, a precomputed table for the actions, and a dot product between them.

What this is and is not

It is a real deployment shape. Encode the actions at build time, ship the vectors as a few kilobytes of JSON, run only the state tower on the client. Adding an action later is a JSON edit, not a retrain. A cross-encoder cannot work this way — it needs a forward pass per candidate, on the client, every time.

It is not Laya, and does not need to be. Laya is 421M parameters because it is general across many decision types. This is 22M because the task is eight buckets. Laya's own card reports 0.362 for its base checkpoint against a 0.461 majority baseline and 0.766 once fine-tuned: the fitting does the work, not the scale.

The honest caveats. A 22-case suite is small. The model is an English sentence encoder, so other languages will fall over. The weights are public, which is fine here and wrong if the fine-tune is your product. And cosine similarity is a ranking, not a calibrated probability — if you want the number to mean something, fit a temperature on held-out labels, as in the previous note.
